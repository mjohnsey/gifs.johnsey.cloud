# stash.johnsey.cloud Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the GitHub Pages gif site with `stash.johnsey.cloud`: public gif and emoji shelves, plus a private admin page that saves items to R2 instantly. Every existing `gifs.johnsey.cloud/gifs/*.gif` URL keeps working byte-for-byte.

**Architecture:** One Cloudflare Worker (TypeScript, Hono) runs in front of everything (`run_worker_first: true`). It serves files from R2 with metadata in D1, a public JSON API, an admin write API checked by a Cloudflare Access JWT, and the old-domain redirects. Everything else falls through to a React SPA built by Vite and served as static assets. PR previews deploy a separate `stash-preview` Worker with its own R2 bucket and D1 database.

**Tech Stack:** TypeScript (strict), React 19, React Router, Vite with `@cloudflare/vite-plugin`, Hono, jose, Wrangler 4, Vitest with `@cloudflare/vitest-pool-workers`, GitHub Actions. Versions checked 2026-11-18: wrangler 4.164.0, @cloudflare/vite-plugin 1.70.0, @cloudflare/vitest-pool-workers 0.23.0, vite 8.3.8, react 19.3.1, react-router 8.5.2, hono 4.13.19, jose 6.2.17, vitest 5.1.1, typescript 7.0.2, tsx 4.23.15, cloudflare/wrangler-action v4.1.3, actions/github-script v9.0.0. Pin exact versions. If peer dependencies conflict (e.g. the vitest pool against vitest 5), use the newest compatible set and note it in the commit.

**Spec:** `docs/superpowers/specs/2026-11-18-stash-design.md` (approved). Read it before starting.

## Global Constraints

- **Never run authenticated `wrangler`/`cf` commands locally.** The machine's Cloudflare login is Michael's *work* account. Allowed locally: `vite dev`, `wrangler dev` with no `--remote`, `wrangler types`, `wrangler deploy --dry-run`, `wrangler d1 migrations apply --local`, and Vitest. Everything remote runs in GitHub Actions with `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repo secrets.
- **Git:** work reaches `main` only through a PR. Create branches with `git switch -c <name> --no-track origin/main` and push with `git push -u origin HEAD`. Check `git status -sb` before every push.
- **Canonical origin:** `https://stash.johnsey.cloud`. Old domain: `gifs.johnsey.cloud`. Admin writes are allowed only when the request host equals the env var `ADMIN_HOST`.
- **File URLs:** `/gifs/<name>.gif`, `/emoji/<name>.<ext>` (ext in `gif|png|jpg`), `/posters/<name>.webp`. Names match `^[a-z0-9]+(?:-[a-z0-9]+)*$`, max 64 chars, unique per shelf across items *and* aliases.
- **The gifs shelf accepts real GIF bytes only.** The rejection copy for video is exactly: `That's a video, not a gif. Try the Giphy or Tenor version, or upload a gif.`
- **URL import cap:** 25 MB (`26_214_400` bytes), max 5 redirects. Refuse IP-literal hosts in private, loopback and link-local ranges, plus `localhost`.
- **`inventory.json` shape:** `{"gifs": {"<name>": "gifs/<name>.gif"}}`, with sorted keys, every gif and alias, and `Content-Type: application/json`.
- **Old domain behavior:** file paths (`/gifs/*.gif`, `/emoji/*.*`, `/posters/*`, `/inventory.json`) are served directly, with no redirect. Every other path returns a `301` to the same path and query on `https://stash.johnsey.cloud`.
- **Palette:** page `#dceaf4`, ink `#1f3b2d`, muted `#476b58`, screen `#3e6550`, accent `#2c6e4b`, signal (Honeysuckle) `#da7da0` only for Copied/Saved confirmations, on-signal `#1f2a24`. Dark: paper `#1a2a21`, ink `#e3eef6`, muted `#b3c6d4`, accent `#8fb89c`, screen `#0f1914`, rule `#33493d`. Font: Bricolage Grotesque (Google Fonts, `opsz,wght@12..96,400..800`).
- **Copy:** sentence case, plain verbs. Buttons: `Copy link`, `Copy :name:`, `Download`, `Save all`, `Delete`. Confirmation: `Copied`. Toasts: `Copied link to <name>`, `Saved <name>`.
- **Posters:** v1 uses **stored posters only**: ffmpeg in the migration, browser-made on admin save. The spec lets the builder drop the Image Transformations path when stored posters cover everything, and they do. Fallback chain: stored poster, then the original gif with `loading="lazy"`.

## Review Focus

1. **A new name that collides with an existing alias** (adding `smh` while `smh` is an alias of `bunk-smh`) must be rejected as taken (409). It must never shadow the alias. *Test in Task 2 (`insertItem rejects alias name`).*
2. **Messy file names in bulk add** (`Robot Parrot.GIF`, `let_me_in (1).png`) must suggest clean slugs (`robot-parrot`, `let-me-in-1`), with the extension lowercased and `jpeg` normalized to `jpg`. *Test in Task 7 (`slugify`).*
3. **Browser and Slack fetch behavior on big gifs:** `HEAD`, `If-None-Match` (expect `304`) and `Range` (expect `206` with `Content-Range`) must work on file URLs. *Tests in Task 3.*
4. **A pasted page URL with a relative `og:image`, or no image at all,** must resolve relative URLs against the page. With no image it fails with `Couldn't find an image on that page.` *Tests in Task 5.*
5. **Deleting an item that has aliases** deletes its aliases too. The confirm text names them, and the R2 object and poster are removed. *Test in Task 6; copy in Task 10.*

**Interfaces:**
- Produces in `src/shared/types.ts`:

  - `interface Item { shelf: Shelf; name: string; ext: Ext; path: string; bytes: number; width: number; height: number; aliases: string[]; posterPath: string | null; createdAt: string }`. `path` looks like `"/gifs/bunk-smh.gif"`.

Schema: one table `items(shelf TEXT NOT NULL CHECK (shelf IN ('gifs','emoji')), name TEXT NOT NULL, ext TEXT NOT NULL, key TEXT NOT NULL, content_type TEXT NOT NULL, bytes INTEGER NOT NULL, width INTEGER NOT NULL, height INTEGER NOT NULL, sha256 TEXT NOT NULL, alias_of TEXT, poster_key TEXT, source_url TEXT, created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')), PRIMARY KEY (shelf, name))`, plus an index on `created_at`. ### Task 6: Access check and admin API

**Files:**
- Create: `worker/access.ts`, `worker/admin.ts`
- Modify: `worker/index.ts`
- Test: `worker/access.test.ts`, `worker/admin.test.ts`

**Interfaces:**
- Consumes: `sniff`, `resolveImage` (Task 5); `insertItem`, `insertAlias`, `nameTaken`, `deleteItem`, `recentItems` (Task 2); `isValidName`.
- Produces:
  - `requireAdmin` Hono middleware. It returns 403 `{"error":"Admin is only available on stash.johnsey.cloud."}` when `ADMIN_HOST` is non-empty and the host differs, and 401 `{"error":"Sign in required."}` when the Access JWT is missing or invalid. It verifies with jose `jwtVerify` against `createRemoteJWKSet(new URL(\`https://${env.ACCESS_TEAM_DOMAIN}/cdn-cgi/access/certs\`))`, with `audience: env.ACCESS_AUD` and `issuer: https://${env.ACCESS_TEAM_DOMAIN}`. It takes the key set as a parameter so tests can inject a local JWKS.
  - `POST /api/admin/resolve` with `{ url }` returns `200` with the image bytes. Headers: `content-type` set to the sniffed type, `x-suggested-name`, `x-source-url`. Video gives 422 `{"error": <video copy>}`, and an `ImportError` gives 422 with its message.
  - `POST /api/admin/items` takes multipart fields `file` (required), `shelf`, `name`, `aliases` (comma-separated, optional), `poster` (webp, optional, gifs only) and `sourceUrl` (optional). It returns 201 `{ item: Item, url: string }`, where `url` is the canonical absolute URL. Errors are JSON `{ error }`: 400 invalid name, 409 `"<name> is already taken."`, 413 over cap, and 422 for a wrong type or a video on gifs (exact video copy).
  - `DELETE /api/admin/items/:shelf/:name` returns 200 `{ deleted: string, aliases: string[] }`, or 404.
  - `GET /api/admin/recent` returns `{ items: Item[] }` (20 newest).
- Emoji accepts `gif|png|jpg`. **WebP is rejected for emoji** unless Slack's current docs say it's accepted (check them in this task and note the source in the commit). For webp, the gifs shelf gives the video-style message `Only GIFs can go on the gifs shelf.`

- `scripts/migrate.ts --env production|preview|local [--limit N]`:

  - It asserts `/inventory.json` contains every snapshot key.
  - With `--expect-redirect-root`, it asserts that `GET <base>/` returns 301 to that URL.
  - It prints a table and exits non-zero on any failure.
